# Разработка

## Текущий статус: игра и локально проверенный рейтинговый протокол

Реализованы каркас, детерминированный движок и локальная игра: SVG-поле,
клавиатура, SVG-джойстик с deadzone/hysteresis и Pointer Capture, отдельные кнопки,
Hold/Next, показатели партии, выбор стартового уровня и перезапуск.
Пауза скрывает фигуры и очередь, останавливает активное время; продолжение через
три секунды. Blur/visibilitychange и разрыв кадров >250 мс вызывают паузу,
а отпускания кнопок записываются в replay на первом возобновлённом тике.
Есть IndexedDB-автосохранение примерно раз в секунду активной игры и при паузе,
blur/pagehide/visibilitychange. Восстанавливаются поле, Hold/Next, PRNG, таймеры
и replay; продолжение только с паузы. Web Locks допускает одного писателя на origin:
вторая вкладка играет без сохранения. При отсутствии IndexedDB/Web Locks или ошибке
записи игра остаётся доступной с предупреждением. Записи старше 7 дней,
повреждённые или с несовместимой версией правил удаляются. Завершённая тренировка
удаляется; рейтинговая партия остаётся до успешной отправки. Это локальное восстановление, не доказательство результата.
Нельзя гарантировать финальную запись при аварийном закрытии или очистке браузером;
в обычных условиях возможна потеря последнего интервала автосохранения. Сохранение
привязано к браузеру и origin: localhost и опубликованный сайт не делят партии.
Добавлены HMAC-сессии, отдельный ValidationDO, отправка завершённого replay,
идемпотентное принятие, публичный Cache API и приватный личный рекорд.
Точный контракт и ограничения — [RUN-PROTOCOL.md](RUN-PROTOCOL.md).
Правила, API и ограничения движка описаны в [GAME-RULES.md](GAME-RULES.md).
В production эти изменения ещё не включены; отдельный staging опубликован и
проверен — [STAGING.md](STAGING.md). Локально для режима
«Рейтинг» нужен ключ в `workers/backend/.dev.vars`; без него выдача отвечает 503.

Нужен Node.js 24 LTS и npm. Никакого аккаунта Cloudflare для локальной разработки.

```sh
npm ci
npm run dev
```

Откройте http://127.0.0.1:5173. Команда сначала запускает backend через Wrangler
на 127.0.0.1:8788, затем Vite. Service Binding `BACKEND` соединяет SvelteKit с
`tetris-backend`. Данные SQLite хранятся локально в `.wrangler`, не в облаке.
Ctrl+C завершает оба процесса. Порты можно изменить через `DEV_PORT` и `BACKEND_PORT`.

```sh
npm run lint
npm run check
npm test
npm run test:integration
npm run build
npx playwright install chromium
npm run test:e2e
npm run test:smoke
npm run test:smoke:built
npm run preview
```

`preview` запускает собранный web Worker и backend локально через Wrangler.
Браузерные тесты запускаются **после build**, используют production-сборку,
Chromium desktop и эмуляцию Pixel 7. Тестируются реальные touch-события, отмена
жеста, клавиатура, пауза, countdown, restart, отсутствие горизонтального overflow
и узкий экран 320×640. Это не проверка на физическом iPhone/Android и не WebKit.
Отдельные браузерные тесты проверяют IndexedDB-reload, повреждение записи,
конкурирующие вкладки, недоступность хранилища и удаление завершённой партии.
Интеграционные тесты используют отдельное временное хранилище и удаляют его.
Smoke-тесты также изолируют SQLite и не затрагивают локальные данные разработчика.
`test:plan` отдельно запускает прежние расчёты из планирования: они не доказывают
проходимость игры, достаточность лимитов или производительность в облаке.

## Маршруты и граница доверия

- `/` — статически подготовленный игровой экран с клиентской гидратацией;
  тренировка по умолчанию, явный выбор рейтинга с серверным seed и уровня 1.
- `/leaderboard` — страница реальных данных без тестовых рекордов.
- `GET /api/health` — проверка web → Service Binding → backend → SQLite.
- `POST /api/runs` — stateless HMAC-сессия без DO/SQLite при старте.
- `POST /api/runs/finish` — ограниченный replay, guest binding, ValidationDO, атомарная запись.
- `GET /api/leaderboard` — топ текущей версии правил, Cache API с TTL 30 секунд.
- `GET /api/leaderboard/me` — личный рекорд по подписанной HttpOnly cookie, `private, no-store`.
- Backend `/results` — **внутренний** маршрут только для доверенного валидатора.
  Не публиковать backend через `workers.dev`, preview URL или HTTP route.
  Локально маршрут доступен на loopback для интеграционных тестов.

Результат принимается одной SQLite-транзакцией вместе с обновлением лучшего счёта.
`run_id` глобально уникален, повтор не изменяет рекорд. Рейтинги разделены по
`rules_version`. Очистка использует индекс срока хранения и подзапрос с LIMIT 50
(прямой DELETE LIMIT не переносим между сборками SQLite). Все timestamps — Unix
миллисекунды. Равные очки не заменяют рекорд; топ сортируется по score DESC,
achieved_at ASC, guest_id ASC. Идентификаторы гостей не публикуются в топе.

Проверка структуры `VerifiedResult` не заменяет серверный replay. Публичный finish
не проксирует клиентские очки к `/results`: итог формирует только валидатор.

## Деплой

Сейчас CI только проверяет и собирает приложение. Секреты и автоматический
production-деплой не настроены; команды разработки ничего не выкладывают.
`npm run deploy:check` делает только dry-run двух Worker.

Первый ручной выпуск выполнен 2026-11-02:
https://tetris-web.nosov-antony.workers.dev. Подробности — [DEPLOYMENT.md](DEPLOYMENT.md).

При явном разрешении на следующий выпуск сначала деплоится backend с SQLite-миграцией,
затем web с Service Binding. Для staging и production нужны отдельные Worker,
DO namespace и секреты; нельзя направлять preview на production-хранилище.
SQLite миграции данных должны быть обратно совместимы при обновлении backend
раньше web. Текущая инициализация схемы — версия 1, дальнейшие изменения требуют
отдельной миграции, а не переписывания начального CREATE TABLE.

## Что дальше

`npm audit` сообщает четыре предупреждения low в цепочке инструментов сборки
SvelteKit из-за `deepmerge` (GHSA-gcqx-w48m-w2h4). В установленной актуальной
версии исправления нет; предлагаемый npm откат SvelteKit до 0.x несовместим
с проектом. Принудительное автоматическое исправление не применяется.

Получены полный action-only марафон, трёхчасовой timeout и 50 000-event fixture;
они прошли локальный workerd и отдельный Cloudflare DO probe — [отчёт](measurements/2026-11-03/REPORT.md).
CPU-поля в этом tail отсутствовали: сетевое время не заменяет CPU-замер.
Сквозной staging полного пути прошёл на коротких реальных сессиях. Следующий шаг —
CPU-телеметрия и дополнительные тяжёлые replay, затем production Secret и migration v2
с разрешением на публикацию. Событийная оптимизация должна проверяться
на полное совпадение состояния с эталоном. Протокол не защищает от ботов.
