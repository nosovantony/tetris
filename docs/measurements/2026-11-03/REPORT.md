# Длинные replay: локальная и облачная проверка

Сессия работ выполнялась 2026-11-03 по локальному времени; timestamps результатов
записаны в UTC и относятся к 2026-11-02 23:21–23:23Z.

## Что измеряли

Впервые используется **настоящий движок Marathon 150**, а не kernels из замеров
2026-11-02. Все replay получены только действиями от штатного начального состояния.
Исходные бинарные файлы и manifest: [tests/fixtures/replays](../../../tests/fixtures/replays).
Генератор — offline-бот с поиском достижимых положений, эвристикой и lookahead 4;
не утверждается проходимость человеком, отсутствие ботов или худший CPU.

| Fixture     | Финал   | Линии | Активных тиков | Событий | Бинарных байтов |
| ----------- | ------- | ----: | -------------: | ------: | --------------: |
| marathon    | won     | 1 500 |         14 607 |  22 719 |          45 446 |
| timeout     | timeout |   266 |        648 000 |  16 424 |          33 525 |
| adversarial | timeout |   266 |        648 000 |  50 000 |         100 677 |

`marathon` фиксирует 3 752 фигуры и итог 15 945 272 очка. Он проходит все уровни,
включая 20G и уменьшенный lock delay, но длится лишь 243,45 активной секунды:
бот играет быстрее человека. `timeout` содержит легальные idle/reset-периоды,
достигает трёх часов на уровне 27, а не доказывает трёхчасовую победу.
`adversarial` добавляет идемпотентные `soft-drop-up` и достигает лимита событий
и максимальных пачек по 32, сохраняя точное состояние timeout-эталона.

Проверяются canonical decode/encode и SHA-256 всего финального состояния,
затем production-функция `validateSubmission`, без событийной оптимизации.
Отдельный негативный вариант обрезает adversarial до 647 999 тиков:
симуляция выполняется до конца, но `playing` должен отклоняться с 422.

## Локальный workerd и облако

Для каждого из четырёх вариантов выполнены три последовательных запроса.
В обоих окружениях получено **12/12 ожидаемых HTTP-ответов**: девять 200 с точными
серверными очками и три 422 для незавершённой партии.

Облачный временный `ReplayProbe` импортирует production-валидатор и выполняет его
в SQLite-compatible Durable Object. Ни SQLite-таблиц рейтинга, ни production
Service Binding в нём нет. Claims намеренно созданы runner-ом в прошлом, чтобы
тестировать большой активный промежуток без трёх часов реального ожидания.
HMAC, выдача сессии, гостевая cookie, публичный web Worker, ratelimit и запись
результата **не входят в этот тест**. Позже сквозной путь короткой партии проверен
на отдельном [staging](../../STAGING.md), без отключения подписи или проверки времени.

Сырые HTTP-результаты:
[local workerd](workerd-local-results.json), [Cloudflare](cloud-results.json).
Они содержат клиентское HTTP wall time, включая сеть, маршрутизацию, cold start
и ответы. Это не CPU-время. Число запусков слишком мало для p95/p99 или SLA.

## CPU: важный пробел телеметрии

В этом запуске Wrangler tail вернул executionModel/outcome/logs, но **не вернул
`cpuTimeMs` и `wallTimeMs`**. См. [очищенный tail](cloud-tail-sanitized.json).
Все 12 DO-логов имеют outcome `ok`, исключений нет. Отсутствие CPU-полей
нельзя трактовать как нулевой CPU, заменять сетевым временем или переносить
числа burn-kernel из прошлых измерений на replay.

Дополнительная попытка запросить DO CPU через GraphQL с существующим Wrangler
OAuth получила HTTP 401 Authentication error — [ответ](graphql-cpu-attempt.json).
Новые полномочия/секреты и платный доступ не запрашивались; обхода авторизации нет.

Подтверждено только, что эти конкретные replay реально прошли в Cloudflare без
ошибки лимита, а не гарантированный запас CPU для всех допустимых replay.
Для дальнейшей оценки нужны CPU-метрики через доступную телеметрию, иные seed,
тяжёлые rotate/hold/20G-потоки и конкурентные запросы. Rate limit приблизительный;
этот тест не доказывает защиту суточных Free-квот при атаке.
Платный план/лимиты не включались; billing API всё ещё независимо не подтверждён.

## Ресурсы и уборка

Worker `tetris-replay-measure-20261103` был защищён случайным `PROBE_TOKEN`,
установленным через stdin Wrangler и не записанным в git/logs. Публичный обработчик
до установки секрета fail-closed. Endpoint принимает ограниченный JSON только
после проверки секрета. Запросов к production-рекордам не было.

После тестов migration v2 удалила ReplayProbe, затем Worker удалён. Отдельный
запрос Cloudflare API подтвердил отсутствие Worker и DO namespace:
[cleanup-verification.json](cleanup-verification.json).
Рабочие `tetris-web` и `tetris-backend` остались. Production не обновлялся.

## Воспроизведение

```sh
npm run fixtures:replay
npm test
npm run bench:replay
```

Облачная команда **создаёт реальные временные ресурсы** в текущем Cloudflare
аккаунте, требует явного разрешения на такой запуск и OAuth Wrangler:

```sh
npm run bench:replay:cloud
```

Runner делает ограниченные 12 запросов, сохраняет только очищенный tail и
пытается удалить DO/Worker в `finally`. При аварийном завершении процесса
`finally` не гарантирован: проверить ресурсы и выполнить cleanup вручную.
Зафиксированное имя временного Worker нельзя переиспользовать параллельно.
Не запускать этот инструмент против production и не заменять им нагрузочные тесты.
