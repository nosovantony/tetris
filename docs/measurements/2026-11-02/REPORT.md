## Статус и границы

Проведены локальные измерения Node.js и workerd. Попытка облачного деплоя
заблокирована отсутствием workers.dev-поддомена аккаунта (Cloudflare API 10063).

Настройки аккаунта, подписка и DNS не менялись. Основной план не редактировался.

**Эти результаты не доказывают, что полный replay укладывается в 10 мс CPU
Workers Free, и не проверяют лимит CPU Durable Objects на Free.**

Разработки игры нет. Код здесь — одноразовый измерительный стенд, а не готовый
движок. Нет SRS, 7-bag, Hold, T-spin и настоящей партии Marathon 150.

## Окружение и воспроизводимость

- CPU: AMD Ryzen 7 5825U with Radeon Graphics, Linux.
- Node.js: v26.13.0.
- Wrangler: 4.156.1; локальная среда workerd через `wrangler dev --local`.
- Время прогретого Node: 100 замеров, по 10 выполнений в каждом, после 30 прогревов.
- Первое выполнение: 20 отдельных процессов Node; запуск процесса/импорт модулей
  не входят в измеряемый интервал. Это не cold start изолята Cloudflare.
- CPU измеряется `process.cpuUsage`: учитывает CPU всего процесса, в том числе
  фоновые потоки V8. Это НЕ метрика CPU time Cloudflare.
- Тайминги localhost HTTP в JSON включают сервер, транспорт и Wrangler:
  их нельзя сравнивать с лимитом 10 мс CPU.
- Фиксированный и событийный счётчики таймеров совпали в 102 сценариях,
  включая 176 срабатываний DAS и события с одинаковым тиком.
  Это проверка только игрушечной модели таймеров, а не корректности Tetris.

Запуск из этой директории (не из корня проекта):

```sh

```

Второй скрипт запускает локальный сервер на 127.0.0.1:18923 и инспектор на
18924, завершает их после теста. Использует npx для Wrangler указанной версии.
Он НЕ выполняет deploy. `wrangler.jsonc` оставлен как описание стенда,
его облачный деплой отдельно не запускать без проверки аккаунта и разрешения.

## 1. Размер журнала

Синтетические журналы: 3 750 условных размещений за 216 000 тиков (час при
60 Гц). Это минимальное число тетрамино по площади для 1 500 линий с пустого
поля. События предназначены только для измерения кодека, не являются
валидными/проходимыми игровыми партиями и не описывают типичный ввод игрока.

Кодек: unsigned LEB128 для дельты тиков + 1 байт actionId.
В этих журналах каждое событие занимает 2 байта. Другой кодек может дать иной размер.
JSON в таблице — массив абсолютных `[tick, action]`, не delta-JSON.

| Событий на размещение | Событий | Бинарно, байт | Base64, байт | JSON-массив, байт |
|---|---:|---:|---:|---:|
| 4 | 15 000 | 30 000 | 40 000 | 157 273 |
| 6 | 22 500 | 45 000 | 60 000 | 235 909 |
| 8 | 30 000 | 60 000 | 80 000 | 314 546 |
| 12 | 45 000 | 90 000 | 120 000 | 479 324 |

Вывод: 20 000 событий недостаточно уже для синтетического профиля с 6 событиями
на размещение. 64 КиБ = 65 536 байт: профиль с 8 событиями проходит бинарно,
но не в Base64; профиль с 12 событиями не проходит даже бинарно.
Токен и обёртки здесь не учтены. Это не основание выбирать новый окончательный
лимит: нужны валидные длинные replay готового движка.

## 2. Локальное вычислительное ядро

Bitboard-ядро: пять O-фигур поперёк поля, очистка двух строк, повторить до
3 750 фигур / 1 500 строк. Проверки столкновений, hard drop, очистка строк, PRNG.
Последовательность намеренно не соответствует 7-bag.
Отдельное ядро таймеров: периодическая гравитация, DAS, lock, упорядоченный ввод.
Таймеры не управляют bitboard; объединённый тест — их последовательный запуск,
а не симуляция игры.

| Тест | Медиана CPU процесса, мс | p95 CPU процесса, мс |
|---|---:|---:|
| Bitboard: 3 750 фигур / 1 500 строк | 0,168 | 0,178 |
| Декодирование 30 000 событий | 0,385 | 1,811 |
| Таймеры: фиксированный шаг | 0,968 | 0,988 |
| Таймеры: событийные переходы | 0,385 | 0,396 |
| Decode + bitboard + событийные таймеры, прогрето | 0,915 | 0,985 |
| То же, первое выполнение в новом процессе | 7,336 | 8,507 |

В основном профиле фиксированный шаг сделал 216 001 итерацию, событийный —
36 301 с тем же итоговым состоянием. В профиле с удержанием DAS: 301 против
184, то есть польза переходов существенно зависит от ввода.

Вывод: пустые тики можно экономить, но дешёвое ядро не измеряет полный replay.
Сюда не входят HMAC, HTTP parsing, валидация недоверенного ввода, SvelteKit,
SRS и полноценная логика игры. По этим цифрам нельзя обещать 2–5 мс в облаке.

## 3. SQL: измеренные rowsRead / rowsWritten локального SQLite DO

| Запрос / данные | rowsRead | rowsWritten |
|---|---:|---:|
| DELETE по expires_at без индекса: 1 000 строк, 500 истекли | 1 000 | 500 |
| Повторный DELETE без индекса: 500 строк, ни одна не истекла | 500 | 0 |
| DELETE с индексом expires_at: 500 строк, ни одна не истекла | 1 | 0 |
| COUNT(score > 5000), 10 000 результатов, индекс score | 5 000 | 0 |
| Топ-100 по score, тот же индекс | 100 | 0 |
| Личный результат по PRIMARY KEY | 1 | 0 |

Счётчики относятся к конкретным запросам, не включают стоимость построения
индексов/заполнения тестовых таблиц. Это локальные показатели runtime, не счёт
из облачного биллинга.

Выводы для плана:
- нужен индекс `runs(expires_at)` и ограниченные порции очистки;
- личный рекорд по ключу дешёв, точное место через COUNT — нет;
- 1 000 таких COUNT по 5 000 строк дают 5 млн чтений — всю указанную дневную
  квоту, без остальных запросов (арифметическая экстраполяция, не нагрузочный тест);
- `strftime('%s','now')` сработал локально и вернул Unix-время в секундах
  как строку. Ранее высказанное предположение о его недоступности не подтвердилось.
  Единицы timestamp всё равно нужно определить явно.

## 4. Кэш — только локальный тест

Пять последовательных HTTP-запросов одним Node-клиентом без HTTP-кэша:

- Только `Cache-Control`: пять разных UUID генерации ответа.
- Явные `caches.default.match/put`: первый MISS, затем четыре HIT с одним UUID.

`X-Probe-Cache` — заголовок нашего стенда, не Cloudflare CF-Cache-Status.
Локальный результат подтверждает работоспособность ветки Cache API в стенде,
но НЕ доказывает работоспособность CDN/Cache API на workers.dev.
Без облачного теста нельзя подтверждать ни TTL на edge, ни обещание
«2–4 обращения к DO в минуту глобально».

## 5. Что заблокировано и как продолжить

- `GET workers/subdomain` вернул 10007: workers.dev-поддомен отсутствует.
- Deploy даже с `workers_dev: false` вернул 10063 с тем же требованием.
- Workers account-settings доступен, но `default_usage_model: standard` не
  подтверждает тариф Free. Subscription API вернул 403: у OAuth нет доступа
  к этим сведениям.
- Список Workers до и после попытки пуст.

Для настоящих облачных измерений сначала владелец аккаунта должен открыть
Workers & Pages в Cloudflare Dashboard и завершить создание workers.dev-адреса,
а также подтвердить Workers Free. Платный тариф включать не нужно.
После этого: временный ограниченный стенд, CPU-нагрузка отдельно в Worker/DO,
извлечение реального CPU time из invocation logs и тест кэша на workers.dev.
Один успешный запрос не будет считаться доказательством гарантированного лимита.
Окончательный бюджет replay измеряется позднее на полноценном движке с
валидными длинными и предельными журналами.
