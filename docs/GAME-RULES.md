# Правила движка Marathon 150 v1

Реализован чистый TypeScript без DOM, Svelte, системных часов и случайности платформы.
Это собственный зафиксированный набор правил с SRS, а не заявление о сертификации
или полном соответствии всем вариантам Tetris Guideline.

## API

```ts
import { createGame, stepGame, ghostPiece, simulateReplay } from '../src/lib/game';

const game = createGame({ seed: 42 });
stepGame(game, ['left-down']);
stepGame(game, ['left-up', 'rotate-cw', 'hard-drop']);
const ghost = game.active ? ghostPiece(game.board, game.active) : null;

const replayed = simulateReplay(
	{ seed: 42 },
	[
		{ tick: 0, action: 'left-down' },
		{ tick: 1, action: 'left-up' },
		{ tick: 1, action: 'rotate-cw' },
		{ tick: 1, action: 'hard-drop' }
	],
	2
);
```

`createGame` создаёт состояние, `stepGame` **изменяет его на месте** и возвращает
тот же объект. Клиентский UI должен уведомлять Svelte об обновлении отдельно.
Состояние содержит PRNG, очередь, кнопки и все таймеры: копируется через
`structuredClone` и JSON. Сервер обязан восстанавливать партию из подписанной
конфигурации и replay, а не принимать присланное клиентом состояние.

## Геометрия и генерация

- Поле 10×20, координаты x=0…9, y=0…19; скрытые строки y=-2,-1.
  В массиве `board` 22 строки: `board[y + 2][x]`.
- Старт фигуры: x=3, y=-2, ориентация 0. Выход за верхнюю границу y=-2 запрещён.
- Mulberry32 с явным uint32 seed, Fisher–Yates 7-bag с rejection sampling.
  Очередь всегда содержит пять следующих фигур. Seed 0 допустим.
- SRS: четыре ориентации, только CW/CCW на 90°, все восемь переходов
  JLSTZ и I с пятью кандидатами. O не перемещается при повороте и не сбрасывает lock.
- Hold разрешён один раз на фигуру, снова доступен после фиксации. При обмене
  фигура возвращается в стартовую ориентацию/позицию; пустой Hold расходует очередь.

## Время и ввод

- Один вызов `stepGame` — ровно 1/60 секунды **активного** времени.
  `state.tick` — число выполненных тиков. Event tick=0 — ввод первого шага.
- Сначала применяются упорядоченные действия, затем DAS/ARR, гравитация, lock.
  До 32 действий на тик. Некорректный пакет отвергается до изменения состояния.
- `left/right/soft-drop-down/up` — переходы кнопок, не автоповторы ОС.
  CW, CCW, Hold и Hard Drop — одиночные действия; debounce делает адаптер ввода.
  Повторный down зажатой горизонтальной кнопки игнорируется.
- Последняя нажатая горизонтальная кнопка имеет приоритет. При её отпускании
  другая зажатая кнопка становится активной с новым отсчётом DAS, без немедленного шага.
- DAS по умолчанию 8 тиков, ARR 1 тик (133⅓/16⅔ мс). Первый сдвиг немедленный,
  первый автоповтор через DAS тиков. DAS: 1…60, ARR: 0…60 целых тиков.
  ARR=0 после DAS сдвигает до препятствия, применяя обычные правила движения.
- Hard Drop фиксирует немедленно. Не более одной фиксации на тик: последующие
  действия этого тика игнорируются, кроме отпусканий кнопок. Новая фигура не
  получает гравитацию/lock в тот же тик. Hold сам по себе не завершает тик.
- Soft Drop — одна клетка за тик, +1 очко за реально пройденную клетку.
  Hard Drop — +2 за клетку. Автоматическая гравитация очков не даёт.
- Гравитация: уровни 1…30 — `round(60-(level-1)*54/29)`;
  31…80 — `round(5-(level-31)*4/49)` с минимумом 1; 81…150 — явный 20G.
- 20G опускает фигуру до опоры при спавне и после успешного сдвига/поворота,
  без деления на ноль. Сдвиги в 20G идут по поверхности, не над ней.
- Lock delay: 30 тиков до уровня 120 включительно; затем
  `round(30-(level-120)/2)`, минимум 15 тиков. Первый тик контакта учитывается.
  При спавне в 20G таймер начинается со следующего вызова `stepGame`.
- Только успешный сдвиг/поворот **с опоры** обнуляет lock, максимум 15 раз.
  После первого контакта таймер идёт и в воздухе. При истёкшем таймере фиксация
  произойдёт при следующем контакте: поднятие kick-ом не даёт бесконечного lock.
- Максимум 648 000 активных тиков (3 часа), затем `timeout`, не Marathon Clear.
  Победа/поражение в последний допустимый тик имеет приоритет над timeout.
  Конечное состояние больше не изменяется, зажатые кнопки сбрасываются.

Пауза, отсчёт перед возобновлением и wall-clock время — вне движка: на паузе
нельзя вызывать `stepGame`. Адаптер должен записать отпускания всех зажатых
кнопок на первом активном тике после паузы. Контракт подписанных токенов,
паузы и сроков отправки описан в [RUN-PROTOCOL.md](RUN-PROTOCOL.md);
replay сам по себе не доказывает человеческую игру и не защищает от ботов.

## Очки и завершение

Очки за очистку умножаются на **уровень до очистки**:

| Событие     | 0 линий |   1 |    2 |    3 |   4 |
| ----------- | ------: | --: | ---: | ---: | --: |
| Обычное     |       0 | 100 |  300 |  500 | 800 |
| T-spin Mini |     100 | 200 |  400 |    — |   — |
| T-spin      |     400 | 800 | 1200 | 1600 |   — |

- T-spin: последним успешным изменением фигуры был поворот и заняты ≥3 угла
  вокруг её центра. Границы поля считаются занятыми. Оба передних угла заняты
  или использован пятый SRS-кандидат — full; иначе mini (triple повышается до full).
  Успешное перемещение, включая вертикальное, сбрасывает признак поворота.
  Неудачное действие и Hard Drop на нулевое расстояние его сохраняют.
- Сложные очистки (Tetris и T-spin/Mini с линиями): Back-to-Back ×1,5 базовых очков
  начиная со второй подряд. Обычная очистка сбрасывает цепочку; нулевая не меняет её.
- Combo начинается с 0 на первой очистке; далее +1 за каждую подряд.
  Бонус `50 × combo × level`; фиксация без линий сбрасывает combo в -1.
- Perfect Clear и другие неоговорённые бонусы не начисляются.
- Ranked: старт только с уровня 1, уровень `min(150, 1+floor(lines/10))`.
  Победа при ≥1500 линий, возможен одновременный финиш до 1503 линий.
  Time Bonus один раз: `max(0, 1500000 - tick*10)`.
- Training: старт 1…150, относительный счёт линий от нуля, прогрессия от стартового
  уровня. Победа после `(151-startLevel)*10` линий. Результат не рейтинговый.
- Block-out: занята стартовая позиция новой/удержанной фигуры.
  Lock-out: фигура целиком зафиксирована выше видимого поля и не очистила линий.
  Частично видимая фигура сама по себе не вызывает поражения. Очистка/победа
  обрабатывается раньше lock-out; после очистки проверяется спавн следующей фигуры.

## Replay v1 и границы готовности

Бинарный формат: `0x54 0x52 0x01`, затем unsigned canonical LEB128
`durationTicks`, `eventCount`, пары `[deltaTick, actionId]`. Отсчёт дельт от нуля,
события одного тика сохраняют порядок. ID действий заданы порядком `ACTIONS`
в `types.ts` (0…9). Кодек версионирован независимо от `rulesVersion`.

Лимиты: 50 000 событий, 128 КиБ бинарного тела, 32 действия/тик, 648 000 тиков.
Это защитные ограничения, **не доказательство достаточности для всех честных партий**.
Строгая проверка заголовка, дельт, переполнений, неизвестных действий, лишних
байтов и неканонического LEB128. События обязаны попадать в `[0,durationTicks)`.
Запрещена симуляция продолжения после конца игры.

`simulateReplay` — эталон с проходом по каждому тику. Игровой экран использует
`GameSession` с requestAnimationFrame и аккумулятором фиксированных тиков;
сам движок не зависит от браузерного времени. Клиентский replay сохраняется вместе
с состоянием незавершённой партии в IndexedDB. При превышении 50 000 событий локальная игра продолжается,
но буфер записи отключается и очищается с предупреждением.

Checkpoint версии 1 содержит rulesVersion, savedAt, полное состояние и replay.
При восстановлении проверяются структура, диапазоны, совместимость версии,
возраст до 7 дней; завершённый статус допускается для рейтингового outbox с ticket.
Проверка не пересимулирует
replay и не является серверной валидацией. Pending actions и доли тика не сохраняются;
на первом возобновлённом тике добавляются releases, исключающие залипание ввода.

HMAC, ValidationDO и приём рейтинговых партий реализованы и проверены локально;
контракт — [RUN-PROTOCOL.md](RUN-PROTOCOL.md). Snapshot не является источником серверных очков.
Полный action-only марафон и трёхчасовые replay проверены в Cloudflare:
[отчёт](measurements/2026-11-03/REPORT.md). CPU-телеметрия и событийная оптимизация ещё впереди. Модульные fixtures очищения линий
вручную задают поле для проверки граничных случаев; это не победный replay.
